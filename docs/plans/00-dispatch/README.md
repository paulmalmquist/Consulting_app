# 00-dispatch — Idea Routing and Classification

This is the entry point for every new idea, bug report, feature request, refactor proposal, or research thread.

Do not start coding. Do not open a backlog item. Route first.

## What happens here

1. Raw idea arrives (from conversation, observation, sales call, test failure, or session discovery).
2. Classify it using `routing-map.md`.
3. Fill out `idea-intake-template.md` to produce a dispatch record.
4. Route to the correct plan folder(s).
5. If a durable decision was made, record it in `decision-log.md`.
6. If a question remains open, record it in `open-questions.md`.

## Files

| File | Purpose |
|---|---|
| `routing-map.md` | How to classify and route any idea |
| `idea-intake-template.md` | Template for a dispatched idea record |
| `decision-log.md` | Durable architectural/product decisions |
| `open-questions.md` | Unresolved questions across all environments |

## Rule

Every coding session that starts from a raw idea must produce a dispatch record before the first file is edited.
Every coding session that ends must update the relevant plan folder and append any reusable lesson to `docs/tips.md`.
