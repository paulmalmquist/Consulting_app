Font choices

Display
Abadi (Monotype, Ong Chong Wah) — humanist sans with subtle editorial character. Slightly condensed proportions and warm terminals give it presence without feeling techy. Used for marketing heroes, section heads, and large numerics.
Sans
Geist — crisp modern sans. Body copy, UI subheads, buttons, table cells. The geometric precision against Abadi's warmth is the core type contrast.
Mono
Geist Mono — pairs natively with Geist. Reserved for IDs, timestamps, labels, command snippets — nothing else.

Rules

Tracking
Display −0.025em. Body 0. Mono labels +0.14em uppercase.
Weights
Display 500 (medium). Sans 400/500. No 700 anywhere. No italics anywhere — emphasis via color or weight only.
Licensing
Abadi is a commercial Monotype face. Self-host WOFF2 in /fonts; the @font-face block at the top of this file picks them up. Fallback stack: Gill Sans (macOS) → Verdana (Windows) → system sans.
Numerics
tabular-nums on all KPIs, tables, deltas.
Mono restraint
Mono is a seasoning, not a base. Never set body copy, section heads, or buttons in mono.

Pills are 4px radius — not fully rounded. No glow, no ring. Dot + short caps label. Same family across every surface.

Card rules

  • 01Edge lighting, not full borders. 1px inset highlight on the top edge (rgba 0.06). Bottom-shadow carries weight.
  • 0212px radius on cards, 8px on controls. Pills at 4px. Never mix.
  • 03Subtle top-gradient wash on elevated surfaces (~2% white over tier color) — gives productized sheen without being a gradient landing page.
  • 04Hover = edge brightens 4%, lift 1–2px. No color swap, no scale, no pulse.

Hierarchy rules

  • 01Contrast carries hierarchy, not color. Primary FG, secondary FG, tertiary FG — in that order, always.
  • 02Accent = meaning. Teal is action or "live." Copper is emphasis or secondary action. Never decorative.
  • 03One accent per surface. Cards with teal numbers don't also get copper chrome.
  • 04Labels are mono, values are display. This contrast replaces the old "everything is monospace" feel.

How this fixes the "terminal look"

  • 01Mono is demoted — only IDs, timestamps, and system labels. Numbers and headlines move to Abadi (humanist sans) with tabular-nums.
  • 02Neon cyan/green replaced with desaturated teal and copper in the same lightness band. Glows removed; weight comes from typography.
  • 03Fully-rounded pills and bright outlines gone. Pills are 4px radius, 1px hairline, caps label — functional, not decorative.
  • 04The screen reads as a product surface, not a console buffer. Same density, new tone.

How this fixes the "generic React SaaS feel"

  • 01No Tailwind-default slate-900 / indigo-500. The palette is custom ink + controlled teal in oklch — recognizably not a starter template.
  • 02Cards use edge lighting and layered depth instead of 1px borders. This is the single biggest shift from "SaaS dashboard" to "instrument panel."
  • 03Type pairing is genuinely distinct, not "Inter for everything." A humanist sans (Abadi) for authority, a geometric sans (Geist) for precision, Geist Mono for system. Three voices, one system.
  • 04Accents are semantic, not decorative. Copper isn't used to make something "pop" — it marks a specific class of state.

Design System Evolution — Marketing vs Terminal

Reusable rules for moving a "competent engineering" UI into a premium product surface, without rewriting layout.

01 · TYPE
Demote mono to a seasoning

Monospace creates a "terminal" feel the moment it touches body copy or headings. Reserve it for IDs, timestamps, labels, and code. Everything else moves to a display/body sans pairing. This single change does more than any color swap.

02 · TYPE
Pair a display cut with a body cut

Don't use one font for everything. Pair a humanist display sans (Abadi, Gill Sans, GT America) for marketing authority with a crisp geometric sans (Geist, Söhne) for UI. The tension between the two is what reads as premium — not a single tight cut of Inter.

03 · COLOR
Ditch Tailwind defaults

Anything sitting on slate-900 + indigo-500 + emerald-500 reads as a template. Define the palette in oklch, keep accents in the same lightness band (~68–72% L), and use ink/graphite/slate tones instead of pure navy.

04 · COLOR
Accent ≠ decoration

Every accent color must carry a meaning. If you can't answer "what does teal mean on this surface," remove it. A good system has 2 accents max (primary + secondary warmth), and the semantic palette sits beside them at the same chroma.

05 · SURFACE
Edge lighting beats full borders

1px borders on cards scream "dashboard." Replace them with an inset 1px top-edge highlight and a soft bottom shadow. This is the single biggest shift from "SaaS panel" to "instrument card."

06 · SURFACE
Build depth, not decoration

Use 3–4 background tiers (base → surface → elevated → raised). Hierarchy comes from tier stepping, not outlines. A popover is raised above a card; a card is raised above a panel. This is how instruments feel layered.

07 · MOTION
Kill the neon glow, keep the discipline

Pulsing dots and glowing pills read as cyberpunk cliché. Replace with restrained transitions: edge brightens on hover, numbers count up, cards lift 1–2px. 120ms ease-out; nothing longer than 280ms.

08 · VOICE
Marketing surfaces & app surfaces share DNA

Same type, same palette, same surface grammar — just different density. The landing page uses the same card chrome as the Orders view. Users arriving from the site into the product should feel zero seam.

09 · DENSITY
Hierarchy via contrast, not decoration

When everything is outlined, nothing is. Drop 80% of borders. Replace them with foreground contrast tiers (primary / secondary / tertiary). If a thing needs to recede, desaturate its text — don't add a box around the things that don't.

10 · IMPL
Tailwind-compatible without a rewrite

All tokens live as CSS variables in :root; extend tailwind.config to reference them (bg-base, bg-surface, accent-teal, etc). No utility changes at the component call-site. One theme file replaces the old palette.
